# 森さんのダッシュボード要件マップ

Updated: 2026-07-24  
Source: 2026-07-24 に依頼者が共有した画面イメージ2点

## 1. 確定した意図

ダッシュボードは、単に指標を一覧するBI画面ではなく、次の順で「今日どこを見るか」「次に何をするか」を判断できる業務画面にする。

1. 現在の状況を一言で伝える
2. 推奨アクションを最大4件に絞る
3. 注意アラートと重要度の内訳を比較する
4. トレンドと主要・補助KPIで根拠を確認する
5. 必要な場合だけ既存のAIチャットドロワーへ相談を引き継ぐ

AIは広告媒体を自動変更しない。ダッシュボード上のCTAは相談文の下書きを作るところまでとし、チャット送信と媒体writeは人間の明示操作を必要とする。

## 2. 画面・操作の受け入れマップ

### DASH-15-01 状況ブリーフィング

- ダッシュボード上部に、キャラクターと吹き出し形式の「今日の結論」を1件表示する。
- 結論は現在選択中の期間、媒体、広告アカウント、campaign階層に対応する。
- 悪化・改善を述べる場合は、対象KPI、比較期間、変化量を同じブロック内で確認できる。
- キャラクターは装飾画像として扱うか、意味を持たせる場合はアクセシブルな名前を付ける。
- 根拠データが不足する場合は断定せず、「比較できるデータが不足しています」などの明示状態にする。

### DASH-15-02 推奨アクション

- ブリーフィング直下に「ちょこっとくん推奨アクション」を最大4件表示する。
- 各カードは、対象、推奨行動、根拠、優先度または期待する観察項目を短く確認できる。
- 4件未満の場合は架空の提案で埋めず、取得できた件数だけ表示する。0件では空状態と次の確認手順を示す。
- カードの「AIに聞く」は既存の右サイドチャットドロワーを開き、対象と根拠を相談文の下書きに設定する。
- CTAだけでメッセージ送信、広告媒体write、承認処理を実行しない。

### DASH-15-03 注意アラートと重要度集計

- アラートは、日付、対象範囲、変化、状態、詳細、相談操作を比較できる表で表示する。
- 表の横または近接位置に、高・中・低など重要度別の件数サマリーを表示する。
- 重要度は色だけに依存せず、テキストまたはアイコンでも区別する。
- 行クリックまたは行内の「AIに聞く」で既存の右サイドチャットドロワーを開く。
- 引き継ぐ下書きには、選択アラート、現在の期間、媒体、広告アカウント、campaign階層を含める。
- ドロワーを開いただけでは送信せず、ユーザーが送信操作を行うまで会話履歴を追加しない。

### DASH-15-04 トレンドとKPIの主従

- トレンドグラフをKPIカード群より先に表示し、現在の期間とフィルタに対応させる。
- グラフ上または直近の操作列で、表示指標と現在選択中の指標を確認・切替できる。
- 主要指標は、広告費、コンバージョン数、CPA、CTRの4件を同じ階層で表示する。
- 補助指標は、表示回数、クリック数、CPC、CVRを主要指標より弱い視覚階層で表示する。
- 各KPIは現在値、名称、単位、比較値がある場合は増減を表示する。算出不能値は`-`とする。
- トレンド、KPI、アラート、AI相談は同じ期間・アカウント・campaign階層フィルタを参照する。

### DASH-15-05 レスポンシブ、状態、アクセシビリティ

- Desktopでは「吹き出し → 4アクション → アラート表＋重要度集計 → トレンド → 主要KPI → 補助KPI」の順を保つ。
- Mobileでは同じ意味順序のまま1列へ積み、表は列を黙って削らず、横スクロールまたは行カード化で情報へ到達できるようにする。
- 主要操作はキーボードで到達・実行でき、ドロワーを開いた後は閉じる操作とフォーカス移動が確認できる。
- loading、empty、error、partial、mock利用中をデータ状態として明示し、空白や実データ風の捏造表示にしない。
- 文字と主要操作は320px幅でも重ならず、DesktopとMobileの両方で横方向のページ全体オーバーフローを起こさない。

## 3. データ対応

| UI | 必要データ | 実装方針 |
| --- | --- | --- |
| 状況ブリーフィング | KPI比較、期間、現在のscope | 既存Dashboardレスポンスから決定的に生成し、根拠不足時は不足表示 |
| 推奨アクション | recommendationまたは異常検知結果 | 最大4件へ整形し、0件を空状態として扱う |
| アラート表 | anomaly、重要度、対象、説明 | 既存異常データを利用し、重要度件数をUI側で集計可能 |
| トレンド | 日別KPI時系列 | 現在の期間・階層filterと同じqueryを使う |
| 主要・補助KPI | cost、conversions、CPA、CTR、impressions、clicks、CPC、CVR | 既存値を再配置し、算出不能は`-` |
| AI相談下書き | 選択したカードまたはアラートと現在scope | 既存チャットドロワーへ下書きとして渡し、自動送信しない |

新しいprovider write APIは不要。既存Dashboard APIで値が不足する場合だけread-onlyの追加フィールドを検討し、UI都合で架空値を補わない。

## 4. Browser E2E

`dashboard-chat-character`シナリオで最低限次を確認する。

1. Desktopでブリーフィング、最大4件の推奨アクション、アラート表、重要度集計、トレンド、主要・補助KPIが意味順に表示される。
2. 推奨カードからドロワーを開くと対象入りの下書きが見え、送信前は会話履歴が増えない。
3. アラート行または「AIに聞く」からドロワーを開くと、選択アラートと現在scopeが下書きへ反映され、送信されない。
4. 期間・アカウント・campaign階層を変えると、ブリーフィング、アラート、トレンド、KPI、相談下書きが同じscopeに更新される。
5. DesktopとMobileで情報順序、キーボード操作、ドロワーの開閉、ページ全体の横オーバーフローなしを確認する。
6. loading、empty、error、partial、mock利用中の各状態が識別可能である。

## 5. 対象外

- 独立したAIチャットページ
- 巨大なBI画面または任意のダッシュボードビルダー
- CTAを押しただけでのチャット自動送信
- Agentからの広告媒体mutation
- Meta Ads / Yahoo Adsの追加実装
